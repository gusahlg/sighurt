# Missing features for sig: the design (deep-design agent, 2026-11-04; adopted by the orchestrator with the notes at the end)

## 1. Verdicts

| Feature | Verdict | Why |
|---|---|---|
| `tab.new [url]`, `tab.duplicate`, `tab.move <left\|right\|n>`, `tab.reopen` | Do now (lane A) | Pure core + command parser; no engine, no chrome, no persistence. `tab.reopen` reuses the session Record path (restore by URL, never claimed exact). |
| Keymap sees the hovered link (`TabInfo::status`) | Do now (lane A) | One field; unlocks "copy link", "open link in new tab" as computed commands in the example keymap. |
| Find in page | Do now (lanes B) | The capability flag exists; every engine but Servo/Wasm/demo has an API; text mode searches the reflowed text itself (covers Servo in the terminal). Servo says Unsupported in the window. |
| History + inline address completion | Do now (lane C) | Bounded, private (0600, same rules as session.toml), one config knob. Completion as a query, never in the Snapshot. |
| Fullscreen (window toggle + page-requested) | Do now, last (lane D) | Plan §17 asks for it "after the basic input contract works". Needs the host, three engine adapters, both chromes. |
| `sig://history`, `sig://downloads` pages; a downloads list | Later | Needs the Snapshot to carry lists and three chromes to draw them. |
| Bookmarks | Not now; document instead | `[keywords]` without `{}` already is a named bookmark (`gh = "https://github.com/"`). sig never rewrites the user's file, so `bookmark.add` has no home. Write it in the README's keywords section. |
| Per-site zoom memory | Never (as logged) | extension-api.md §1.10 left per-site zoom out (decision 29). |

## 2. API shapes

### Lane A: tab commands and the keymap's view (api commands.rs, keymap.rs; core state.rs, tabs.rs; default-config.toml; README)

```rust
// sighurt_api::commands::Command
/// `tab.new [address]`: a tab on the home page, or on `address` as `page.open` takes it.
TabNew(Option<String>),
/// `tab.duplicate`: a new tab after this one, at the selected tab's address (history not copied).
TabDuplicate,
/// `tab.move left|right|<n>`: move the selected tab one step (wrapping) or to position n (from 1).
TabMove(TabMove),            // enum TabMove { Left, Right, To(NonZeroUsize) }
/// `tab.reopen`: open the most recently closed tab again, at the end, and select it.
TabReopen,
/// `location.focus [text]`: the address line, with the address selected; with `text`, the line
/// holds `text` instead, caret at its end (what `/` and `:` keys use).
LocationFocus(Option<String>),

// sighurt_api::keymap::TabInfo  (non_exhaustive; `new` gains the argument)
/// The page's status text: the hovered link, as the page reported it. Page data.
pub status: Option<&'a str>,
```

Core: `BrowserState.closed: VecDeque<SessionTab>` bounded at `MAX_CLOSED = 10`; `close_tab` pushes the tab's session record (the same path `session()` uses) before closing its views; `tab.reopen` pops and restores through the existing restore code (a Record reloads its URL: "never exact"). Not persisted across restarts. `tab.move` is a `Vec::swap`/`remove+insert` plus `active` fixup, `fx.chrome = fx.session = true`.

`location.focus text`: core emits `Effect::Focus(Chrome)` then a new `Effect::LineText(String)` (ordered); `sighurt_ui::extension::ChromeEvent::LineText(String)` replaces the line's text (bounded by the editor's 32 KiB cap), caret at end; the terminal's `open_address` then sets the editor. The example keymap binds `:` to `location.focus :` and `/` to `location.focus /`.

### Lane B: find in page

Commands (api commands.rs): `page.find <text>` (`PageFind(String)`, trimmed, never empty, cut to `MAX_FIND = 1024` bytes at a char boundary — longer is refused with a notice), `page.find-next`, `page.find-previous`, `page.find-stop`. Case: smart case computed in the core (`case_sensitive = text.chars().any(char::is_uppercase)`); wrap-around always on. No `find.*` area: the search belongs to the page.

Engine contract (api engine.rs, events.rs):

```rust
// EngineCommand
/// Find in the view's document ([`EngineCapabilities::find_in_page`]). One search per view:
/// a new `Search` replaces the last, and its highlights. Unsupported engines refuse.
Find(FindCommand),

#[derive(Clone, Debug, PartialEq, Eq)]
pub enum FindCommand {
    /// Start or replace the search; selects the first match from the view's current position.
    Search { search: RequestId, text: String, case_sensitive: bool },
    /// Move to the next / previous match, wrapping around.
    Next, Previous,
    /// End the search and clear its highlights.
    Stop,
}

// EngineEvent (replaceable per view: only the latest counts)
/// What the view's search found, after a `Search`, `Next` or `Previous`. `current`/`total`
/// are 1-based when the engine knows them: WebKit reports only `total`, NetSurf only `found`.
/// Numbers only, so nothing to contain. Dropped by the core when `search` is not the view's
/// current search or `document` is no longer its document.
FindResult { view: ViewId, document: DocumentGeneration, search: RequestId,
             found: bool, current: Option<u32>, total: Option<u32> },
```

Add it to `EngineEvent::view()` and the replaceable list in `pump`'s doc. Capability truth per engine: WPE true (total only: `webkit_find_controller_search` + `found-text(match_count)`/`failed-to-find`, `search_next/previous`, `search_finish`; flags CASE_INSENSITIVE | WRAP_AROUND), CEF true (`cef_browser_host_t::find(text, forward, match_case, find_next)` + `cef_find_handler_t::on_find_result(count, active_match_ordinal, final_update)`, `stop_finding(clear_selection=1)`), Ladybird true (the shim already pushes `LB_EV_FIND_RESULT(current, total)`; the Rust side needs `find_in_page`/`_next_match`/`_previous_match` entry points), NetSurf true (`browser_window_search(bw, ctx, flags, text)`, `browser_window_search_clear`; its `status(found)` callback gives `found` only), Servo/Wasm/demo false (`EngineError::Unsupported`; the core never sends `Find` to an engine whose capability is false, exactly as it never sends `SetZoom` without `page_zoom`, and shows a notice "<engine> can't find in page").

Core (tabs.rs View): `find: Option<Find { search: RequestId, text: String, case_sensitive: bool, found: Option<bool>, current: Option<u32>, total: Option<u32> }>`. Dropped at a `NavigationCommitted` with a new document and on `ViewFailed`; `page.find-next/previous` with no search is a notice ("Nothing to find: page.find <text> first"), never an engine call. Only one search per view; the `search` id is what makes a late result stale.

Snapshot (ui state.rs): `pub find: Option<FindSnapshot { text: String /* contained, ≤ 1024 chars */, found: Option<bool>, current: Option<u32>, total: Option<u32>, supported: bool }>` for the active tab; `contain` cuts `text`. Chromes render "3 of 12", "12 matches" (no current), "no matches", "not supported by servo". Not the status line, so it never fights the hovered link.

Chromes. The line with a `/` prefix is the find field, the way `:` is the command line (decision 19): standard chrome `ui/sighurt-ui/src/chrome.rs` (the `:` branch near line 791) and terminal `frontends/sighurt-tui/src/app.rs` (near line 2050) gain the `/` branch. While the line starts with `/`, each edit issues `ChromeAction::Command(PageFind(rest))` (incremental); Enter runs `page.find-next` and keeps the line open; Shift+Enter `page.find-previous`; Escape runs `page.find-stop` and leaves the line. These are the line's own editing keys. The example keymap binds `/` → `location.focus /`, `n`/`N` in NORMAL → `page.find-next`/`page.find-previous`.

Terminal text mode. The Servo/WPE text view needs no engine: add `Frontend::find(&mut self, view: ViewId, command: &FindCommand) -> bool` (default false, the `page_input` pattern, TUI.md §4); the runtime offers every `Effect::Engine { Find }` to the frontend first. In text mode the TUI returns true and searches the text document itself (a `TextView::find(doc, text, case, direction)` over the lines' sanitized text, focusing the line), showing "n of m" in its bottom line from its own state; the core's `find` stays `found: None` and the chrome shows the text only. In graphics mode the engine does it. `sig --dump` is untouched.

### Lane C: history and completion

Ownership. Policy in the core, clock and file in the runtime. The core reads no wall clock, so it emits facts:

```rust
// Effect
/// A page the user may want again committed in `tab`, or its title arrived: record it
/// ([`Config::remember_history`]). Never for `sig:`, `about:`, `data:`, `blob:`, `javascript:`
/// URLs, views of an engine with `storage = "ephemeral"`, failed loads, or URLs over 8 KiB.
Visited { url: String, title: Option<String>, commit: bool },
/// `site.forget <host>` / `history.clear`: drop the visits of `host`, or all of them.
ForgetVisits(Option<String>),
```

Emitted at `NavigationCommitted` (commit: true) and at the first `TitleChanged` of that document (commit: false, upsert the title). New command `history.clear` (new area, no argument). `site.forget [host]` also emits `ForgetVisits(Some(host))`.

Runtime `crates/sighurt-runtime/src/history.rs` (new; frontend-neutral): `History { visits: BTreeMap<String, Visit { title: String, last: u64, count: u32 }> }`, bounded `MAX_VISITS` by evicting the oldest `last`; `complete(prefix, 8)`: prefix match on the URL with `https://`, `http://` and `www.` skipped, newest first. Loaded at start, saved by a writer like the session's (latest snapshot, debounced, atomic write, fsync, 0600, lock shared with the session's, broken file kept aside, never written when another sig holds the lock). File `{state_dir}/sighurt/history.toml`:

```toml
version = 1
[[visits]]
url = "https://example.com/"
title = "Example Domain"     # contained, ≤ 200 chars
last = 1793800000            # unix seconds
count = 3
```

Parsing follows `Session::parse`: a damaged entry is left out with one notice, unknown fields noticed, another version refused whole.

Config `[history] remember = true` (false: nothing recorded in memory or on disk, completion off; the file is left as it is). Default on. Documented next to `[session]` in default-config.toml. Version stays 1.

Completion API (ui extension.rs): not a Snapshot field.

```rust
ChromeAction::Complete { request: RequestId, prefix: String },   // the line's text, after an edit
ChromeEvent::Completions { request: RequestId, matches: Vec<Completion> }, // ≤ 8, contained:
pub struct Completion { pub url: String /* ≤ 32 768 */, pub title: String /* ≤ 200 */ }
```

The GUI answers synchronously from the runtime's History (in memory); a reply for an older request is ignored by the chrome. Standard and line chromes show inline completion (ghost text after the caret; Right/Tab accepts; a line starting with `:` or `/` never completes). The terminal's line editor gets the same ghost text; its chrome asks the app, which asks the runtime. Not a list: no dropdown surface.

### Lane D: fullscreen

Window-level. `browser.fullscreen` (toggle). Core keeps `fullscreen: bool` = what the window is, from the frontend's reports, and emits `Effect::SetFullscreen(bool)`; the frontend reports the outcome as `BrowserEvent::Fullscreen(bool)` (GUI: the xdg configure's FULLSCREEN state, `frontends/sighurt-wayland/src/window.rs` gains set/unset fullscreen on the sctk Window and the state in `HostEvent::WindowConfigured`; terminal: answers immediately). `Snapshot::fullscreen: bool`; a chrome whose snapshot says fullscreen lists no surfaces and sets `layout.page` to the window (the Snapshot is sent on every core change, so no new ChromeEvent). Terminal chrome: zero chrome rows. Escape does not leave the user's own fullscreen; the keymap binds it (`f11 = "browser.fullscreen"` in the example).

Page-requested. A fact, not a request, because Servo (`notify_fullscreen_state_changed`) and CEF (`on_fullscreen_mode_change`) only notify:

```rust
// EngineEvent, ordered (not replaceable: true then false both matter)
/// The document entered or left element fullscreen inside the view. The browser answers
/// policy with `ExitFullscreen` and the window's own state.
FullscreenChanged { view: ViewId, document: DocumentGeneration, fullscreen: bool },
// EngineCommand
/// Leave element fullscreen; `FullscreenChanged { fullscreen: false }` follows.
ExitFullscreen,
// EngineCapabilities
pub fullscreen: bool,   // servo, wpe, cef true; ladybird, netsurf, wasm, demo false
```

Core policy (`View.fullscreen: bool`): accept only when the view was activated within the existing 5 s activation rule, else send `ExitFullscreen` at once. Accepted: `SetFullscreen(true)` unless the user already had it. While the shown view is fullscreen, a fresh unmodified Escape press is taken by the core before the keymap and sends `ExitFullscreen` — plan §17's "reliable way to reach browser controls", a core rule like Ctrl+A in the address line is the chrome's; needs a line in CLAUDE.md's keys rule. Leaving the tab, closing the view, a new document, `WindowFocus` lost, or the window leaving fullscreen (compositor) all send `ExitFullscreen`; window fullscreen returns to the user's toggle.

Adapters: Servo — implement `notify_fullscreen_state_changed` (queue the event) and `WebView::exit_fullscreen` for the command (both confirmed in the pinned 0.7 source: ~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/servo-0.7.0/webview_delegate.rs:981, webview.rs:696); the page area becoming the window is just new metrics. CEF — `on_fullscreen_mode_change` → event; `exit_fullscreen` → command (capi already has both). WPE — set `enable-fullscreen` true; the adapter's own `WPEToplevel` subclass (`platform.rs`) implements the `set_fullscreen` vfunc: queue the event and call `wpe_toplevel_state_changed(toplevel, state | WPE_TOPLEVEL_STATE_FULLSCREEN)`; `ExitFullscreen` clears the state bit the same way (verify in 2.52's sources that WebKit's WPE Platform view exits element fullscreen when the toplevel loses FULLSCREEN; else the `WebKitWebView` leave-fullscreen path). Ladybird/NetSurf: capability false, nothing wired.

## 4. Strains and answers

- Chrome commands take no argument: unaffected; find text travels as `page.find <text>`; `location.focus [text]` is where the one argument goes.
- The status line as the only notice channel: find results would fight the hovered link; hence `Snapshot::find`. The terminal's bottom line gains a right-aligned find field.
- The Snapshot is whole and re-sent: completion candidates are a query, never a field.
- `bindings` can't use the hovered link: `TabInfo::status` fixes it for `example`; a `[keys]` table still can't compute (decision 116). Don't add template substitution to `[keys]`.
- Fullscreen's Escape: the first key the core takes before the keymap. Scope it to "a page's element fullscreen is on in the shown view" only.
- The core reads no clock: history timestamps come from the runtime.

## Amendments after GPT-6 Astra's review (orchestrator, 2026-11-04 16:30; these override §2 where they differ; the full review is astra-features-review.md)

### Lane A
- `TabInfo::link: Option<&str>` replaces `status`: a document-scoped hovered link set from `StatusTextChanged` only when the text is a URL the router opens as an address (http, https, file), ≤ 8 KiB (longer → None, never shortened), cleared on a new document and when the status stops being that link. `y f` copies it.
- Reopen stack: `ClosedTab { url, title, engine (chosen), zoom }`, MAX_CLOSED 10, pushed only by closes that removed a tab; `tab.reopen` checks MAX_TABS first and restores through the `tab.new <url>` path with the engine and zoom. `tab.duplicate` keeps chosen engine and zoom. `tab.new` alone keeps today's focus behaviour.
- Find field: `page.find [text]` — no argument opens the chrome's find field (its own editor mode with a `/` prompt; never a `/` prefix on the address line). `location.focus [text]` stays for `:`. Overlong find text is refused at parse time.
- `page.exit-fullscreen` command; `TabInfo::fullscreen: bool` so the example keymap binds Escape → `page.exit-fullscreen` while the page holds element fullscreen.

### Lane B (find)
- Identity on every operation: `Search { search, document, text, case_sensitive }`, `Next { search }`, `Previous { search }`, `Stop { search }`. Adapters stamp results with the id of the native operation they answer; where the native API gives no correlation (Ladybird's shim callback, WebKit's signals), the adapter issues a native stop/finish before a new search and drops callbacks it can tell are from a stopped search (CEF's monotonic identifier); the core drops results whose `search` or `document` is not current. The residual risk (a late old result labelled with the new id before the new result arrives) is bounded by the replaceable event and documented in the API doc.
- One result path: the core emits `Effect::Find { view, command }` for every find command on a view (not only when the engine has the capability). The runtime offers it to `Frontend::find(&mut self, view, &FindCommand, events: &mut Vec<BrowserEvent>) -> bool` (the `page_input` pattern, with the event queue); if the frontend declines and the engine has `find_in_page`, the runtime sends `EngineCommand::Find`; otherwise it queues `BrowserEvent::FindResult { .., supported: false }`. The TUI in text mode answers with the same `FindResult` event, so the chrome's `Snapshot::find` is filled identically. Text mode searches the logical text (the document's lines before wrapping) and maps matches to rendered rows; positions refresh on a new snapshot or relayout; a mode switch (text ↔ graphics) with an active search runs `page.find-stop` and says so.
- Field semantics: the find field is the chrome's editor mode entered by `page.find` with no argument (prompt `/`). Each edit runs `page.find <text>` (incremental); empty text runs `page.find-stop`; Enter accepts the current match, closes the field and returns the keyboard to the page keeping the search (so `n`/`N` continue); Escape closes the field and runs `page.find-stop`. Tab change or the editor closing for another reason closes the field without stopping the search. Whitespace-only text is not searched. "n of m" shows in `Snapshot::find`, drawn by the chromes beside the address line (standard, line) and on the terminal's bottom line.
- Stale by document: the core drops the view's `find` at a new document and on `ViewFailed`; the WPE adapter calls `search_finish` at commit if WebKit does not clear highlights itself (verify).
- Capability truth: an engine says `find_in_page: true` only once its adapter is implemented and exercised by a test in that engine's suite.

### Lane C (history)
- Eligibility: http and https only; URLs with userinfo (`user:pass@`) skipped; fragments stripped; ≤ 8 KiB; only commits that push a new document (not reload, traversal, same-document `pushState`/`replaceState`), only the shown view's user-visible navigations; never when the engine's launched storage is ephemeral, never for `--dump` (`Paths { session: None }` → no history either), never for sig:, file:, data:, blob:, javascript:.
- Titles: a title updates the visit of (url, the accepted commit's document generation) the core remembers for the view; after a clear, or with no such visit, a title does nothing.
- Deletion is acknowledged: `Effect::ForgetVisits { request: RequestId, host: Option<String> }`; the runtime deletes in memory, drops any pending save, writes the file at once (also with `remember = false`), and reports `BrowserEvent::VisitsForgotten { request, outcome }` (done; or "another sig owns the history file: forgotten here only" when this instance does not own the lock). The `.broken-*` copies are not covered (say so in the doc).
- Store bounds: MAX_VISITS 5 000; entries older than 90 days dropped at load; the file is refused before parsing when over 4 MiB (kept aside, notice); the writer keeps one latest snapshot (a one-slot mailbox, not an unbounded channel), debounce 30 s, written only when changed; a second instance (not the lock owner) loads the file for completion and never writes it, with one notice.
- `remember = false` at a live reload: the in-memory list and pending writes are dropped; the file stays.
- Completion: the runtime owns `History::complete(prefix) -> Vec<Completion { url, title }>` (≤ 8; `Completion` lives in sighurt-runtime — the TUI and the GUI both depend on it; sighurt-ui gets its own mirror type in the chrome API). Inline suffix completion only: the typed text must be a prefix of the candidate's URL after optionally skipping `https://`, `http://` and `www.`; accepting replaces the line with the candidate's exact URL (navigable, never the contained display form). Ghost text and outstanding replies are dropped when the editor closes, the tab changes, the line enters `:` or find mode, history is cleared or disabled, or the text changes. Accept only with the caret at the end and no selection.
- Privacy doc: README and default-config.toml list history beside the session and the engines' storage in the "what sig keeps" recipe.

### Lane D (fullscreen) — window fullscreen first; page fullscreen gated
- Three states in the core: `fullscreen_wanted` (the user's toggle), `window_fullscreen` (observed from the frontend's `BrowserEvent::Fullscreen(bool)`), `page_fullscreen: Option<(ViewId, DocumentGeneration)>`. `browser.fullscreen` flips `wanted` and emits `Effect::SetFullscreen(bool)`; the host reports state-only configure changes (fix window.rs's comparison); a compositor-driven exit resets `wanted`.
- The chrome keeps controls reachable: in fullscreen it lists its surfaces only when needed — the keyboard is in the chrome (address or find field), a notice is showing (`status` is Some), or it draws the page area (sig://home, errors); otherwise it lists none and `layout.page` is the window. The core shows a notice when a page enters fullscreen ("<host> is fullscreen; Escape leaves it") so there is a trusted indicator.
- Page fullscreen acceptance: only for the shown view's current document, with the window focused, consuming an activation within the 5 s rule (so the same activation can't re-enter); otherwise `ExitFullscreen` at once. On leaving by any path (Escape, tab change, new document, view closed, focus lost, compositor exit, the user's toggle) the core clears `page_fullscreen` immediately and restores the chrome and the window without waiting for the engine's confirming event; a later `FullscreenChanged { true }` without a fresh activation is answered with `ExitFullscreen`.
- Escape: the named command `page.exit-fullscreen`, bound by the example keymap (Escape in the page context while `TabInfo::fullscreen`). Safety override in the core: while the shown view holds page fullscreen, an unmodified Escape press that the keymap did not consume runs `page.exit-fullscreen` and consumes the release through the existing `KeyState` tracking; documented in CLAUDE.md's keys rule as the one guarantee a configuration cannot remove.
- Engines advertise `fullscreen: true` only once entering, denial and exit are demonstrated by a check in that engine's suite (Servo and CEF first; WPE after its exit path is verified in 2.52's sources).
- Terminal: window fullscreen is "not available in this frontend" (notice); page fullscreen events are accepted with the same policy and shown as the notice only (the page keeps its rows).
