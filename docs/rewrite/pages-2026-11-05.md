# Internal pages as Wasm guests: help, the configuration, a terminal (5 November 2026)

The user (5 November 2026): "add in a command called help that opens a new tab for you in the
browser that has a website with all relevant sig information and help that a new person might
need. The page should use pure wasm through sig's wasm engine. … adding in new commands in the
configuration should not mean you hardcode it into the browser, the browser simply provides a low
level API that the configuration can use to define keybindings and behaviour of the user's choice.
… Add in more different sig pages that have sig information and help. Also it would genuinely be
pretty cool if you could go and see and edit your configuration inside of the browser. See if you
can add in a sig://terminal that is like a super simplified and wasm-sandboxed terminal. It would
be cool if you could for example use it to launch nvim inside of the browser and edit your
configuration from inside of browser. This idea might be totally crazy and stupid." Also: "add
in a command in my configuration that closes the current tab when I click d."

This document is the design: the orchestrator's proposal as reviewed and corrected by the
deep-design agent (below, verbatim), with the orchestrator's binding decisions first. Where the
decisions and the review differ, the decisions win.

## Binding decisions (orchestrator)

1. Everything in the review's "Verdict" is adopted: page identity is the view's, fixed for life
   and recorded by the core; the pty is split (the core authorises, the runtime spawns and owns
   the child, the engine carries bytes on the master fd); the guest names no program
   (`Shell | EditConfig`); no `browser.help` — user-defined commands instead; `TabInfo.internal`
   for keymaps; `sig://terminal` behind `[pages] terminal = false`.
2. User-defined commands: `Command::Custom { name, argument }` for a bare kebab-case word with
   no dot; resolved by the core from a `[commands]` table (name → one or more built-in command
   strings, validated at load, no recursion, at most 64 entries, an argument appended to the
   last command when it takes one); the default configuration has
   `help = "tab.new sig://help"`. An unknown bare word is the error it is today.
3. The example configuration binds `?` and `f1` to `help`, and `d` to `tab.close` (the user has
   no config.toml: the example configuration is their configuration).
4. Pages: `sig://help` (sections by path: `/` start, `/keys`, `/commands`, `/config`, `/pages`,
   `/engines`, `/terminal-frontend`, `/about`), `sig://config`, `sig://terminal`. `sig://home`
   stays the chrome's. The help page's content comes from the browser where it can (the active
   keymap's bindings through `Keymap::describe()`, the command table with its docs from
   `sighurt-api`, the `[commands]` table, the build's engines, versions, paths), so it cannot
   go stale; prose that explains concepts lives in the guest.
5. Escape and INSERT: on the terminal page only (`TabInfo.internal == Some("terminal")`), the
   example keymap's INSERT passes Escape to the page and `ctrl-\ ctrl-n` leaves INSERT; on
   every other page decision 134 stands unchanged (INSERT takes only an unmodified Escape).
6. The typing guard is adopted: the core drops key and text input meant for the page for
   500 ms after a tab selection the user did not command (a tab that closed itself, a page
   that opened one), so keystrokes in flight never land in another page, a live shell least
   of all.
7. `sig://terminal` ships disabled (`[pages] terminal = false`); with it off the page says how
   to turn it on. SECURITY.md says plainly that the page is a shell with the user's full
   rights and that the Wasm sandbox contains the terminal emulator, not the shell.
8. Lanes and file ownership as in the review's "Lanes" (lane 0 infrastructure + help + the
   command; lane 2 the config page; lane 3 the terminal). Lanes 2 and 3 start at once on the
   files only they own and integrate when lane 0's API has landed.

## Amendments after GPT-6 Astra's review (orchestrator, binding; they override the decisions above and the review below where they differ; the review is [reviews-pages-astra.md](reviews-pages-astra.md))

A1. **Input after an involuntary selection is held, not timed** (replaces decision 6). When the
    shown page changes without the user commanding it (a tab that closed itself, a crash, a
    page-opened tab that takes the front), the newly shown page gets no key, no text, no paste,
    no input-method commit and no `page.send-key` until the user deliberately takes it: a
    pointer press on the page, or any browser command the user runs (a key the keymap
    consumed, a command line, a tab selection). No amount of time and no ordinary character
    unlocks it. A notice says so. Discarded input grants no activation. Separately, keys held
    down across any change of the shown view are released in the old view and their repeats
    and releases are not delivered to the new one. Browser controls stay usable throughout.
A2. **The pty's lifetime is specified, with states** `Opening → Open → Closing → Closed` in the
    core's record: the allowance (one per document, eight per process) is reserved from
    `Opening` through teardown; a cancellation during the spawn, a reply after cancellation, a
    failed delivery to the engine, a guest trap, the child's own exit and `[pages.terminal]
    enabled` turned off all end in `Closed` with the child signalled and reaped. A terminal
    survives while its tab is in the background; it is closed when its page becomes a history
    entry (the tab navigates away), when the tab closes, on reload, on quit and on runtime
    shutdown, and the runtime begins closing ptys before engine shutdown can stall. An
    answered `PtyOpen` is tracked by the core as an open session, not by leaving the request
    in `Requests`.
A3. **No file descriptor in the API type.** `ServiceReply::Pty` carries an opaque session id;
    the master is handed from the runtime to the engine once, by a take-once native transfer
    keyed by that id (decide the smallest mechanism: e.g. the runtime's reply path giving the
    engine an owned fd through a method on the Wasm runtime, not through a cloneable value).
    The guest never sees an OS fd: its handle is the session id, valid only for its current
    document. The data plane is non-blocking with an explicit cancellation wake-up (a wake
    pipe or eventfd in the poll set), cancellable queue waits and an orderly reader exit;
    closing stops writes and discards queued input at once. Guest API, minimal:
    `open(Shell | EditConfig, cols, rows) → handle`, bounded non-blocking `read`, `write`
    returning the bytes accepted, `resize`, `close`, and a status distinguishing running, end
    of file, cancelled and exited(status).
A4. **An honest cleanup contract.** Guaranteed: the directly spawned child is signalled
    (SIGHUP to its process group, then SIGKILL after the grace period) and reaped; no zombie
    and no child of `sig` remains. Best effort: jobs the shell put in other process groups,
    programs that ignore SIGHUP after `disown`, detached sessions — they can survive, as in
    any terminal, and the docs say so. Use a pidfd (or hold the unreaped child) so a delayed
    signal can never reach a recycled pid.
A5. **Internal pages get no network at all**: an explicit deny-all policy enforced in every
    networking host function (fetch, WebSocket, SSE, RTC, media, module loads); today an
    absent policy falls back to "public hosts allowed". Privilege comes only from embedded
    bytes selected through the page registry: a downloaded copy of the same guest, a manifest,
    a reported URL or an import name grants nothing. The engine fixes the exact page name per
    view (help, config and terminal never exchange grants through reload, traversal or
    history). Child instantiation clears every privileged field explicitly (`load_module` uses
    `..parent.clone()` today). Session restore classifies the address again and trusts no saved
    engine or identity. Grants are per operation (help: info; config: config operations;
    terminal: pty). `PtyOpen` and `ConfigWrite` require the selected, focused tab's shown
    document and a deliberate action in it (a consumed activation).
A6. **The spawn recipe**: every descriptor created close-on-exec atomically; argv, environment
    and paths prepared before `pre_exec`, which allocates nothing, logs nothing and takes no
    lock; in the child: a new session, the slave as controlling terminal and as fds 0–2, the
    foreground process group set, the signal mask cleared and ignored dispositions restored to
    default (Rust ignores SIGPIPE; `sig` installs handlers), sane termios and the size set on
    the slave independently of any outer terminal; a failure to seal descriptors is a failed
    launch, never a silent continue. The environment: `sig`'s, minus the listed variables and
    `LINES`/`COLUMNS`, built without touching the parent's; it is hygiene, not isolation —
    credentials, agent sockets and shell startup files remain available to a full-rights shell,
    and SECURITY.md says so. Configured commands and `$VISUAL`/`$EDITOR` are split into a
    literal executable and arguments, never through `sh -c`; the config path is its own
    argument. `TERM`/`COLORTERM` advertise only what the emulator supports (tested with nvim).
A7. **Config writes**: serialize `sig`'s writers with a lock file next to the resolved target,
    reread and compare under the lock, distinguish a missing file from an empty one, bind the
    read to the target it will replace; the race with a non-cooperating external editor is
    documented, not denied. A dedicated writer: an exclusively created temporary file in the
    target's directory, the target's mode kept (0600 when new), no change to the parent
    directory's permissions (the session writer's helper tightens its directory to 0700: do
    not reuse it for a symlink's target), fsync and rename.
A8. **Paste keeps its identity through the native contract.** The terminal frontend turns a
    paste into a `TextInputEvent` commit and the Wasm view strips control characters from text:
    carry a paste marker in `sighurt_api::input` (lane 0), keep order, deliver printable key
    text once, bound the `sig` input queue by bytes and records and clear it when the document
    is replaced; the Wasm view reports an editable state for internal pages so the terminal
    frontend's paste gate lets pastes through. Paste policy per page: the config editor keeps
    tabs and newlines; the terminal page removes ESC and other C0 controls except tab and
    newline/carriage return, prevents a bracketed-paste terminator from being injected, and
    wraps the paste when the program enabled bracketed paste. Inner terminal output is never
    forwarded to an outer terminal.
A9. **User-defined commands stay validated.** `Command::Custom` is produced only for a name the
    `[commands]` table defines: `CommandSet` gains the configured names, so a misspelt bare
    word is still an error when the configuration loads (keys, keymaps, buttons) and in the
    command line, where the line stays open with the error as it does today. Version one:
    aliases take no argument (`help` → `tab.new sig://help`; a typed argument is an error);
    each alias expands to at most 8 built-in commands, validated whole at load; no recursion;
    at most 64 aliases; expansion runs through the same ordered executor as `RunAll`, with
    the activation semantics of how it was invoked.
A10. **Settings**: `[pages.terminal] enabled = false` and `[pages.terminal] command = "…"`
    (a TOML key cannot be both a boolean and a table). Decision 5 stands as written: the
    `ctrl-\ ctrl-n` exit exists only on the terminal page.

# Design review: internal Wasm pages, config editor, `sig://terminal`

Read-only review; nothing was built or run. Line references are from the files as they stand on `config-ext`.

## Verdict

The proposal is sound in shape. Six changes matter:

1. **Page identity is a property of the view, fixed for its life, and recorded by the core.** It is never derived from `ServiceRequest.origin` or from a URL the engine reports.
2. **The pty is split.** The core authorises it, the runtime spawns and owns the child, and the engine only gets the master fd for the bytes. The Wasm engine crate contains no spawn code.
3. **The guest never names what runs.** It picks from a closed set (`Shell`, `EditConfig`); the runtime builds argv, environment and cwd. The start needs a key press in the page.
4. **No `browser.help`.** Bare-word commands are the configuration's: `[commands] help = "tab.new sig://help"`. This is the user's own principle applied to their own request.
5. **Escape is solved with a read-only fact for the keymap** (`TabInfo.internal`), not a page-requested keyboard grab.
6. **`sig://terminal` ships behind `[pages] terminal = false`** until the criteria below are shown.

## A. Embedding: keep (a), the nested cargo build

Reject committed blobs. Three lanes would conflict on binaries constantly, a staleness test can only hash sources, and the terminal blob would be privileged code nobody can review against its source.

Exact shape:
- **Guests** are workspace members under `pages/`, so they share `Cargo.lock`: `sig-page-kit` (guest-side library), `sig-page-help`, `sig-page-config`, `sig-page-terminal`.
- **`crates/sighurt-pages/build.rs`** runs `$CARGO build --release --locked --target wasm32-unknown-unknown -p … --target-dir $OUT_DIR/pages`.
  - Remove `RUSTFLAGS`, `CARGO_ENCODED_RUSTFLAGS`, `CARGO_BUILD_RUSTFLAGS`, `CARGO_TARGET_DIR` and `CARGO_BUILD_TARGET` from the child's environment.
  - Emit `rerun-if-changed` for `pages/`, `sdk/sighurt-sdk` and `Cargo.lock`.
  - Never use the shared `target/wasm32-…` directory (cargo's build-directory lock).
- **Escape hatch:** `SIGHURT_PAGES_PREBUILT=<dir>` skips the nested build. This is for the NixOS package, which is not in the repo and which I could not inspect.
- **Dependency direction:** `sighurt-pages` is an optional dependency of `sighurt-runtime` under `engine-wasm`, with no new feature. The engine does not depend on it; it receives `(name, bytes, grants)` through `WasmConfig`. The core receives names and grants through `Environment`. Both come from one `PAGES` const, so they cannot diverge.

What I checked:
- `sig`'s `--exclude-libs` is a `rustc-link-arg` in `/home/gusahlg/repos/sighurt/apps/sighurt-browser/build.rs`, not an environment flag, so it does not leak into the wasm build.
- `sighurt-tui` already enables rustix `pty`, `termios` and `process`, so adding them elsewhere does not change the default feature set or rebuild Servo.
- `.github/workflows/ci.yml` installs the wasm32 target at lines 35 and 100. Confirm the job running the workspace commands is one of them.
- `vt100` and its dependencies add lock entries only; add them without `cargo update`.

## B. Routing: keep, with changes

- **A new `Route::Page(name)` variant**, not `Route::Engine("wasm")`, so every match site has to decide.
- **The core canonicalises** to `sig://<lowercase-name>/<path>?…`. `sig:help`, userinfo and ports are "no such page". The engine does an exact host lookup.
- **One name is one module, one grant set, one view.** Use `sig://help`, `sig://help/keys`, `sig://help/commands`, `sig://help/about` (path selects the section, `push_state` inside), plus `sig://config` and `sig://terminal`.
- **A view is internal for life.** `navigate` at `/home/gusahlg/repos/sighurt/crates/sighurt-core/src/state.rs:1371` reuses a view when the engine matches. It must also require the same page identity, otherwise `sig://help` and a routed `https://…/app.wasm` share a view and its engine-side history.
- **The engine enforces the same.** In `view.rs`, the first load fixes the view's kind; a `sig:` load in a web view, or the reverse, is `NavigationFailed`. Navigate, Reload and Traverse all go through `View::load`, so that is the one place.
- **Enforce the opener rule in `navigate` itself** (`By::Page { internal }`), not only in `refused()` at `state.rs:2425`, so a new caller cannot forget it.
- **Internal documents get** origin `sig://<name>`, no network policy, no manifest fetch, and refusals for `api_load_module`, URL workers, the file picker and media capture. Today `origin_str` in `/home/gusahlg/repos/sighurt/engines/sighurt-engine-wasm/src/url.rs` gives every `sig:` URL the origin `"sig"`, so the pages would share kv, session storage and `push_state` scope.
- **Chrome and keymap** see no engine label for internal pages.
- **Session restore** routes again and starts nothing.
- **A disabled Wasm engine** gives a clear tab error.

Limitation to state in the docs: Wasm has no `semantics`, so `sig://help` is unreadable in a terminal without graphics, and `sig --dump sig://help` fails. `/home/gusahlg/repos/sighurt/frontends/sighurt-tui/src/app.rs:197` suggests `chrome.text-mode`, which will not work for these pages; give them a notice of their own.

## C. Privileges: keep the `"sig"` module, with changes

- **Two independent layers.** The linker registers `sig` only when `HostState.internal` is `Some` (it derives `Default`, so it fails closed), and every function checks the grant. Then the core checks again from its own `View.page` record.
- **Children never inherit it.** `instantiate` at `/home/gusahlg/repos/sighurt/engines/sighurt-engine-wasm/src/runtime.rs:218` is also used by workers and `api_load_module`.
- **Wrappers live in `pages/sig-page-kit`**, not in `sighurt-sdk`, which stays Apache-2.0 with the `oxide` ABI untouched. The `sig` ABI is unversioned because guests ship inside the binary.
- **`info` does not include the config text.** That belongs to `config`.
- **`pty` carries no argv.**
- **Add an ordered input queue to `sig`** in the infrastructure lane: press and repeat with modifiers, text, and paste as its own record kind. The SDK only has polled `key_pressed`, `text_input()` and a three-bit `modifiers()`, which loses order and cannot tell a paste from typing. Both the editor and the terminal need this.
- **Clipboard copy:** Wasm guests have none today (`capabilities.rs:1675`). Map a `sig` request onto the existing `Service::ClipboardWrite` and its activation rule. Paste arrives as input.

## D. Where the work is done: one mechanism, pty hybrid

**API.** `Service::Page(PageRequest)` with:
- `Info(kind)`, `ConfigRead`, `ConfigCheck { text }`
- `ConfigWrite { text, replaces }`
- `PtyOpen { program: Shell | EditConfig, cols, rows }`

Replies are `ServiceReply::Text` and `ServiceReply::Pty(PtyHandle)`, where `PtyHandle` wraps `Arc<OwnedFd>` with manual `Eq` and `Hash`.

**Guest ABI.** `request`, `poll`, `reply` and `cancel`, plus `pty_read`, `pty_write`, `pty_resize` and the input queue.

**Engine.** The Wasm view currently ignores `ResolveServiceRequest` (`view.rs:398`); that must be implemented.

**Core policy** (one `Requirement::Page` arm in `/home/gusahlg/repos/sighurt/crates/sighurt-core/src/permissions.rs`):
- The grant comes from `View.page`.
- `PtyOpen` also needs `[pages] terminal`, a consumed activation, and a count limit of one per document and eight per process.
- A pty request stays in `Requests` after its answer. The existing cancellation on document replacement, view close and quit then emits `Effect::CancelService`, and the runtime kills the child.
- I did not read how answered requests are removed today; that path needs a small change.

**Runtime** (new `crates/sighurt-runtime/src/pty.rs`):
- Open the pty with rustix; spawn with `Command` and `pre_exec`: `setsid`, `TIOCSCTTY`, and `close_range(3, ~0, CLOSE_RANGE_CLOEXEC)`. Mark CLOEXEC rather than close, so std's exec-error pipe survives.
- Working directory is `$HOME`, or the config directory for `EditConfig`.
- Environment is `sig`'s, minus what `main` set (`JSC_*`) and minus `TMUX*`, `STY`, `KITTY_*`, `TERM_PROGRAM*`, `WEZTERM_*`, `VTE_VERSION`, `WINDOWID`, `SIG_*` and `SIGHURT_*`; plus `TERM=xterm-256color` and `COLORTERM`.
- The program is `[pages.terminal] command`, else `$SHELL`, else `/bin/sh`. `EditConfig` is `$VISUAL` or `$EDITOR` on the config path.
- A waiter thread reaps. Cancel sends SIGHUP to the process group, waits a grace period, then SIGKILL.
- The runtime keeps no clone of the master, so a `sig` crash hangs the session up in the kernel.

**Engine data plane** (new `engines/sighurt-engine-wasm/src/pty.rs`):
- A reader thread fills a 1 MiB queue and stops reading when it is full, so the child blocks.
- Writes are non-blocking with a 64 KiB queue.
- It is dropped with the `HostState`.

**Why not put it all in the engine:** the core would be blind to the most privileged operation in the browser, the setting would be restart-only, and the engine would need the user's environment and paths, which `WasmConfig` says it never picks.

## E. Terminal guest: keep `vt100` in the sandbox; change the Escape plan

- **Reject a page-requested keyboard grab**; it is a mode-jail primitive for web pages.
- **Add `TabInfo.internal: Option<&str>`**, taken from the core's record. A URL check is spoofable by an engine-reported URL.
- **In the example keymap's INSERT**, Escape passes to the page when `internal == Some("terminal")`, and `ctrl-\ ctrl-n` leaves INSERT everywhere. That is nvim's own terminal-mode exit and is encodable with legacy keys under tmux.
- **`Ctrl+[` alone is not enough:** in the terminal frontend it is the same byte as Escape.

Guest rules:
- Process at most about 64 KiB of output per frame. Frame fuel is 50M instructions, and a flood would otherwise end the view with "fuel limit exceeded".
- Answer only fixed-content queries (DA1, DSR, CPR). Never reflect data: no title report, no OSC 52.
- Strip ESC and other C0 controls from pastes, and wrap them when bracketed paste is on.
- Batch cell runs when drawing.
- A hidden tab steps once a second, so its child drains slowly. Document it.

## F. Commands: change

- **No `Command::BrowserHelp`.** Add `Command::Custom { name, argument }`, parsed from any bare kebab-case word with no dot.
- **The core resolves it from a new `[commands]` table:** name to one or more built-in command strings, validated at load, no recursion. The default is `help = "tab.new sig://help"`.
- **The chromes need no change.** They only parse and forward, at `ui/sighurt-ui/src/chrome.rs:898`, `frontends/sighurt-tui/src/app.rs:2479` and `extensions/sighurt-chrome-line/src/lib.rs:504`.
- **Bindings:** `?` and F1 to `help`, `d` to `tab.close`.
- **Help content needs two additions:** `Keymap::describe()` (the trait has no way to list bindings today) and one table of command docs in `sighurt-api`.

## G. Config editor: keep, with changes

- **Stale-write guard:** `ConfigWrite { text, replaces }` is refused when the file no longer equals `replaces`. This covers a second `sig` and nvim in `sig://terminal`.
- **Validation happens in the core** before the effect, with debounced `ConfigCheck`.
- **Reload explicitly after the write** and return the outcome, including "restart needed". The inotify watch covers only the config directory, so it misses a symlinked target.
- **Symlinks:** replace the resolved target. A read-only target (a home-manager store path) is refused with a message.
- **Size cap** of 256 KiB.
- **A missing file starts as `version = 1` plus a pointer to `sig://help/config`**, not a copy of the documented default. A copy would pin every default into the user's file.

## Security holes and their closures

- **A web page reaching an internal page:** `OpenRequested` in both dispositions, `NavigationRequested`, guest `history_back` across documents, `push_state`, session files, and `page.open-in`. Closed by the choke point in `navigate`, a view per page, and engine refusals. Do not register an `x-scheme-handler/sig`.
- **A web guest reaching `sig`:** closed by the linker, the per-function grant, the core's record, and the fact that there is no pty in its `HostState`.
- **Typing into the wrong page (open, needs a decision):** a tab that closes itself hands focus, and the user's keystrokes, to its neighbour, which may be a live shell. I recommend the core drop page key and text input for about 500 ms after a tab selection the user did not command.
- **Primary-selection paste:** a middle click reaches the page even in NORMAL (decision 134). Sanitise as in E.
- **Pty outliving its view:** closed by the held request, the `HostState` drop, and kernel hangup. Children that ignore SIGHUP survive, as in any terminal; say so.
- **Running `sig://terminal` in the terminal frontend:** works as a graphics image, without Escape under legacy keys. Harmless.
- **Multiple `sig` instances:** ptys are independent; config writes are covered by `replaces`.
- **Wording:** the sandbox contains the emulator, not the shell. SECURITY must say `sig://terminal` is a shell with the user's full rights.

## Before `terminal = true` becomes the default

1. The boundary tests below pass.
2. The child has only fds 0 to 2, the scrubbed environment, default signal dispositions and a controlling tty.
3. No orphan or zombie after tab close, navigation, reload, quit, SIGTERM, a killed compositor, or a soak of 100 open-and-close cycles.
4. A 60-second output flood keeps RSS bounded, does not fail the view, and leaves other tabs responsive.
5. nvim is usable in the window: Escape, chords, resize, alternate screen, and no startup hang on unanswered queries.
6. The typing-into-the-wrong-page guard is decided.
7. SECURITY and README are updated, and the user's decision is logged in STATUS.

## Tests that prove the boundaries

**Core, no engine:**
- Routing table and its fuzz: `Page` only for known names.
- Every page-initiated path, for each of `sig://terminal`, `SIG://terminal` and `sig:terminal`, is refused.
- No view reuse across page identity.
- `Service::Page` is denied with a spoofed `origin`, from a non-internal view, without the grant, without activation, with the setting off, from a stale generation, and over the limit.
- A held pty is cancelled on navigate, close and quit.
- A restored terminal emits no `PtyOpen`.
- `Command` round trip including `Custom`.

**Wasm engine:**
- A web or `file:` guest importing `sig` fails to instantiate.
- Cross-kind navigations fail.
- An internal document gets no network, no `load_module`, no worker.
- A cross-page `push_state` is refused.
- A grant check emits no event.
- A stale answer is dropped.

**Runtime:** the fd, environment, signal, tty and resize checks; cancel and SIGKILL grace; the config cases (invalid, stale, symlink, read-only, mode 0600, reload reported).

**`sighurt-pages`:** each blob imports only `oxide` and `sig`, and every `sig` import exists in the engine.

**End to end:** a `pages` scenario in `apps/sighurt-browser/tests/headless.sh`, orphan checks in `faults.sh`, the terminal soak in `soak.sh`, and a no-graphics notice in `apps/sighurt-browser/tests/tui.rs`.
